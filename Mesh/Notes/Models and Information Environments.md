# Models and Information Environments

This is the theory under every NUU Cognition tool. It is a working stance, not a closed system.

## Two axioms

1. One shared external reality exists.
2. Minds construct models. Sensors bring information in. Models are built from that information. There is no direct access to reality. There are only models about it.

Everything inside a Flint is a model: every note, every shard, every type. A Flint is the thinking technology that minds, human or machine, use to build, share, refine, and operate on models.

There is no third layer. There are no categories in the world. Every category is a model that someone built for a purpose.

## Information environments

A model means something only inside an **Information Environment (IE)**. An IE is a mind, or a context that acts like a mind, that knows how to read the model. Examples: a human mental state at one moment, the context window of a language model, or a loaded shard with its knowledge and templates.

Models do not travel alone. When you write a note, you write it for an expected IE. When you read a note, you load it into your current IE. To make a model portable, carry the IE with it, or document the IE that it assumes.

## The model note

The atomic unit of the Mesh is the **model note**. A model note is a bounded container. It holds one model of one thing. Its title is the handle for the model. Once a concept is captured in a note, another note can reference it by title instead of explaining it again. See [[The Mesh]].

## Records and synthesis

Every note sits on a spectrum. At one end is transcription: a transcript, a log, a photograph. The producer added little meaning. At the other end is synthesis: a concept note, a spec, an essay. A record attests that a capture happened. It does not attest that the content is true.

## Traits, not categories

Do not sort models into categories. Describe them with traits, and let types emerge as named clusters of useful traits. Traits are optional. Examples: time (past, present, future), epistemic state (described or predicted), scale, resolution, aliveness (active, retired, superseded), and commitment (draft, working, canonical).

A type such as `(Task)` is not a discovery about the world. It is an engineering choice. It exists because it produces a specific output. A type that helps no operation should not exist.

## Usefulness is the only test

A model, a type, or a structure is justified by what it lets a mind do. Structure is lossy on purpose. It drops information to make the rest operable. Add structure at the moment it pays for itself, not before.
